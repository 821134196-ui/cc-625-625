# 航班特殊餐食确认与装机核对系统

旅客申请特殊餐后，客服、配餐员、机组沿**同一份订单记录**依次确认，确保餐食最终送到正确的航班和座位。

## 一键启动

```bash
./start.sh          # 默认端口 8000
./start.sh 8080     # 指定端口
```

脚本自动完成：定位 PHP（系统 PHP 或 `.tools/` 内置静态 PHP）→ 安装依赖 → 构建前端 → SQLite 迁移 + 演示数据 → 启动服务。打开 http://localhost:8000 即可使用。

技术栈：PHP 8.3 · Laravel 13 · React 19 · Eloquent · SQLite。航班接口（`/api/mock/flights`）与扫码接口（`/api/flights/{id}/scan`）均为本地模拟。

## 三个工作台

| 页面 | 角色 | 功能 |
|---|---|---|
| 客服台 | 客服 | 录入申请、确认餐食类别、改签、换座、取消申请 |
| 配餐站 | 配餐员 | 按航班查看任务、开始制作、打印/重打标签、出库 |
| 机组装机 | 机组 | 扫码接收、查看应收/实收/缺口、确认处理缺餐、关闭装机 |
| 订单记录 | 全员 | 每份订单的完整确认链（事件时间线 + 标签历史） |

## 核心流程与规则

1. **客服确认类别** → 自动生成配餐任务（绑定当前航班+座位）。
2. **配餐员制作** → 打印标签（唯一条码 `M-XXXXXX`，含航班/座位/餐别/受限标识）→ 出库到航班。
3. **机组扫码装机** → 装机页实时显示 **应收（已出库）/ 实收（已扫码）/ 缺口**。
4. **改签/换座**：未装机的餐食跟随订单调整 —— 旧标签立即作废（旧航班**不能继续出库**，扫旧条码被拒），任务回到待制作并指向新航班/座位，需重新打印标签。
5. **取消申请**：释放待制作任务，作废未装机标签，从应收中移除。
6. **受限餐（过敏/医疗/宗教）**：缺餐时**不得擅自用普通餐替代**（前端禁用该选项，后端强制拦截并记录 `substitution_rejected` 事件）。
7. **少餐**：缺口自动出现在装机页，机组必须选择处理方式并确认；存在未处理缺口时**不能关闭装机**。
8. **重复扫码**：同一条码只计一份，第二次返回 `duplicate`，实收量不增加，缺口不消失。

## 验证

```bash
cd app && php artisan test
```

10 个特性测试覆盖：完整链路、改签后标签/任务归属一致且旧航班不能出库、换座后标签一致、已装机订单禁止调整、取消释放任务、受限餐不可替代、重复扫码幂等、缺口可见且阻塞关闭、错航班/未知条码拦截。

```

app/                Laravel 应用
  app/Services/     业务规则（MealOrderService / CateringService / LoadingService）
  config/mealtypes.php  餐食类型与受限规则
  resources/js/     React 前端（客服台 / 配餐站 / 机组装机 / 订单记录）
  tests/Feature/MealFlowTest.php  关键不变量测试
```
